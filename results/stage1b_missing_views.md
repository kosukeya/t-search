# Stage 1B Result — Missing Local Views

Status: **completed B3 coverage-loss experiment**.

## Question

B1/B2 retained one view per event and removed one adjacency-report direction. B3 instead restores the full Stage 1A local view

`V_e = (id_e, Pred_1(e), Succ_1(e))`

but removes one or more whole event-owned views.

The experiment asks what happens when **coverage**, rather than adjacency direction, is reduced.

The detailed reconstruction semantics are fixed in `docs/stage1b_missing_views_protocol.md`.

## Two reconstruction policies

### Strict observed-node policy

Only surviving view owners count as events.

Referenced IDs without their own surviving views are recorded as dangling references but are not promoted into the reconstructed block.

### Referenced latent-node policy

A referenced ID may introduce an event even if its own view is missing.

The event universe is restricted to:

`Owners union Referenced`.

Edges reported by both surviving endpoints are doubly reported. Edges touching a missing-view event may be singly reported.

An event that is neither a surviving owner nor referenced anywhere is not reintroduced from knowledge of the original block; it is classified as lost.

## Case A — remove only `V_d`

Surviving owners:

`{a,b,c,e,f}`

### Strict policy

Reconstructed events:

`{a,b,c,e,f}`

Reconstructed direct edges:

`{a->b, a->c}`

Dangling reference:

`{d}`

Therefore strict observed-node reconstruction does **not** recover the canonical block.

### Latent policy

`d` is referenced by surviving views from `b`, `c`, `e`, and `f`, so it is promoted to a latent event.

Doubly reported edges:

- `a -> b`
- `a -> c`

Singly reported edges:

- `b -> d`
- `c -> d`
- `d -> e`
- `d -> f`

Observed result:

- events: 6
- direct edges: 6
- labeled equality: true
- unlabeled graph isomorphism: true
- reachability equality: true
- latent events: `{d}`
- candidate completions: 1

Thus:

`B_latent = B_1`

for this single-view deletion.

### Interpretation

A missing event-owned perspective can be structurally reconstructed when every incident edge is still reported by the surviving opposite endpoint and shared global IDs remain available.

This is a reconstruction result only. It does not imply that an event ontologically exists because other events refer to it.

## Case B — remove `V_b` and `V_d`

Surviving owners:

`{a,c,e,f}`

Both `b` and `d` remain referenced, so the latent policy recovers the full event set:

`{a,b,c,d,e,f}`.

Evidence-backed direct edges are:

- `a -> b`
- `a -> c`
- `c -> d`
- `d -> e`
- `d -> f`

The original edge

`b -> d`

has no surviving report because both endpoint views are absent.

Latent events:

`{b,d}`

Under the closed-world event universe and DAG constraint, the unresolved relation between `b` and `d` admits exactly three labeled completions:

1. no direct edge between `b` and `d`;
2. `b -> d`;
3. `d -> b`.

Observed result:

- compatible completions: 3
- original canonical block among candidates: true
- original canonical block uniquely selected: false

### Interpretation

This is the first Stage 1 result where **event identities remain reconstructible but a relation between reconstructed events becomes ambiguous**.

The surviving local data determine that `b` and `d` exist in the candidate event universe, but do not determine their direct relation.

This is not yet ontic Potentiality. It is model-theoretic / epistemic ambiguity generated by missing local evidence.

## Case C — remove `V_d` and `V_e`

`d` remains referenced by surviving views, so `d` is recovered as latent.

However, `e` was referenced only by `V_d`. Once both `V_d` and `V_e` are removed, no surviving view mentions `e`.

Observed latent reconstruction:

- events: `{a,b,c,d,f}`
- `d` recovered as latent: yes
- `e` recovered: no

### Interpretation

A completely unreferenced missing event is **lost** under the B3 closed-world reconstruction policy.

The reconstruction algorithm deliberately does not consult the original `B_1.events` to restore it.

## Focused validation

Six focused B3 checks passed:

1. strict single-missing reconstruction keeps only view owners;
2. latent single-missing reconstruction exactly recovers the canonical block;
3. two adjacent missing views create latent-edge ambiguity;
4. the three expected DAG completions are enumerated;
5. a completely unreferenced missing event is lost;
6. inconsistent reports between two surviving owners are rejected.

The previous Stage 1A/B1/B2 suite had 15 passing tests before this isolated B3 module was added.

## Property classification

### Local observable

For each surviving view owner:

- event ID;
- immediate predecessor IDs;
- immediate successor IDs.

### Reconstructible

Under the latent policy, a missing event and its incident relations are reconstructible when the missing event remains referenced and every relevant relation has at least one surviving endpoint report.

Case A demonstrates exact reconstruction.

### Ambiguous

A direct relation between two latent events can become ambiguous because neither endpoint view survives to report it.

Case B produces three compatible DAG completions.

### Lost

An event that is neither a surviving view owner nor referenced by any surviving view is lost under the stated closed-world policy.

Case C demonstrates this with `e`.

### Strict invariant

None is claimed.

Global event IDs are still privileged and the reconstruction depends on explicit coverage and closed-world assumptions.

## Main lesson

B1/B2 showed that **directional redundancy** was unnecessary for reconstruction in a complete labeled family.

B3 shows that **coverage is more consequential**:

- one missing perspective may be recoverable from neighboring relational reports;
- multiple missing perspectives can preserve event identity while making relations among those latent events ambiguous;
- sufficiently hidden events can disappear entirely from the reconstructible world.

This produces a useful structural distinction for Stage 2:

`compatible global completions != ontic future possibilities`.

Stage 1B has now generated compatible alternatives without assigning them any ontological interpretation. Stage 2 can later compare an epistemic reading with an ontic-Potentiality reading without building the latter into the reconstruction machinery from the start.
